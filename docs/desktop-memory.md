# 桌面端与长会话内存优化

## 回收策略

- **状态查询不加载全文**：`agents/jobs/output/skills` 等读取与控制接口使用冷会话。发送代理消息仍按需升级热态，模型上下文与原有权限边界不变。
- **空闲会话降温**：现有 30 秒后台扫描会释放非运行、没有正在使用的句柄的热会话事件、偏移表和派生上下文缓存。SSE 订阅不阻止降温；会话摘要、计费、目标、权限、标题保留。未闭合轮次不会降温。
- **步骤结算即回收**：前后端在 `assistant-message` 到达后清除已结算步骤的流式碎片，不等整个多步骤轮次结束。JSONL 日志仍完整保存每条事件。
- **隐藏窗口不积压帧**：窗口隐藏时用定时批处理替代可能暂停的动画帧，并在可见性变化时切换调度器；卸载取消两类回调与历史分页请求。
- **轻量计费缓冲**：只保留轮次/步骤边界与 usage，不再克隆回答、工具结果、系统提示词或 chunk 引用数组。轮次结束释放缓冲容量。
- **有界前端窗口**：首次和向前翻页目标由 500 调整到 200 个展示事件；完整用户消息组可能超过目标。对话处于底部且轮次结束时，超过 600 个事件便退回最近约 200 个事件；向上阅读和轨迹视图不自动裁剪。完整历史可以重新分页加载，轮次轴仍保留全部锚点。单个超大轮次不强行拆分。
- **屏外渲染回收**：离滚动视口超过 800px 的消息卸载 Markdown、代码高亮和组件树，以实测高度占位。用户消息锚点、乐观发送行保留；已展开交互内容和焦点所在行不自动卸载。滚回时恢复内容。
- **文件正文按需加载**：文件标签仍保留，但只驻留当前激活文件正文；切换、重试和卸载取消旧请求，重新激活时从磁盘读取。
- **高亮器按需加载**：Shiki 与基础语法移出首屏包，不再在空窗口启动时下载/执行或预热高亮器；首次显示带语言的代码块时加载，期间保持纯文本可读。

## 验证

```powershell
cd D:\Denia\web
pnpm check:memory
pnpm build
cd D:\Denia
cargo test -p denia-session --lib
cargo test -p denia-server --lib state::tests
cargo test -p denia-server --lib api::runtime::tests
cargo test -p denia-agent-loop --lib
```

合成测试包含 10,000 个 chunk 的结算回收、重试与跨轮次分隔、2,000 轮持续窗口裁剪、1,000 个代码行容器的卸载/恢复、历史锚点、文件标签切换与请求取消，以及后端降温/恢复、计费一致性和运行中保护。

一次本地 Node/jsdom 合成测试中，1,000 个代码行容器仅保留 12 个挂载内容，DOM 元素由 82,000 降到 1,972，强制 GC 后 JS 堆由约 396.3 MiB 降到 64.5 MiB。2,000 轮共 8,000 个事件的尾部窗口仅保留 324 个事件。组件集成测试同时验证底部裁剪、保留全部导航锚点、历史阅读不裁剪、隐藏窗口批处理，以及快照重置时取消过期分页。

这些结果用于验证回收机制，**不是 Tauri/WebView2 整个进程的内存降幅**。生产测量应使用相同 release 构建、相同日志和视口，统计 Denia 与其 WebView2 子进程的 Private Bytes 和 Working Set；分别观察启动、长会话底部、历史回看、连续运行、结束后 30–60 秒和切换会话后的占用。不使用清空系统工作集掩盖真实内存占用，也不删除历史日志。

## 生效与取舍

前端构建后还需重新构建桌面端，才能更新嵌入式控制台：`cargo build --release -p denia-desktop`。不需要迁移或清理用户数据。

回收后再次查看旧消息或文件会增加一次解析/读取；首次代码高亮可能比预热方式稍慢。手动大量加载历史、轨迹视图、单个超大轮次及多个展开卡片仍可能占用较多内存，不承诺恒定进程内存上限。
